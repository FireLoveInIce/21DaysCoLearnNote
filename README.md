# 21天共学笔记

## 项目简介

本项目用于记录链上学习过程。我为自己制定了一个 21 天学习计划，希望能够坚持完成，并在学习、实践和复盘中有所收获。

## 个人情况

目前我是一名纯套利小白，主要用于记录和分享自己的学习过程，也希望得到更多建议与指导。此前我的代码主要提交到公司私有仓库或仅在本地运行，因此也想借此机会在 GitHub 上留下一些公开的学习记录。

## 学习方向

学习方向专注于 DEX，并以 EVM 生态为主、SVM 生态为辅。选择这一方向，是因为从个人体感来看，DEX 中出现机会的频率相对更高。

## 21 天学习计划

整体目标：打牢基础，将认知逐步转化为能够监控、判断和执行的程序化系统。

### Day 01—05：理解 Uniswap 的迭代与核心机制

学习 Uniswap V2、V3、V4 的迭代过程，重点理解 V3 和 V4 的工作逻辑。

目标：

- 理解各版本的关键变化与设计取舍。
- 掌握核心合约接口及 ABI，能够识别后续开发所需的主要调用入口。

### Day 06—11：建立套利基础认知

学习套利相关知识。结合个人当前的资金、基础设施和执行能力，本阶段聚焦以下方向：

> DEX 内套利、DEX 间套利、跨链套利、三角套利和稳定币套利分别为什么出现？真正执行需要什么条件？又最容易死在哪里？

清算暂不作为学习和执行方向；主动 MEV 策略也不作为盈利目标。MEV、抢跑和交易排序只作为套利执行中的风险因素进行学习和建模。

目标：

- 对常见套利原理和应用场景形成基本认知。
- 能够分析某个具体场景，初步判断是否存在可执行空间。
- 理解手续费、滑点、流动性、延迟、抢跑、交易失败等主要风险因素。

### Day 12—16：将认知程序化并搭建监控系统

把前期认知转化为程序，初始化自己的系统，重点建设监控体系。面对各种场景和机会，我认为需要构建一个属于自己且适合自己的系统，对信息进行归纳、总结和分类。机会出现后，如果完全依赖手动操作，往往会慢人一步。

目标：

- 完成监控系统的初步设计与实现。
- 使用具体案例验证系统链路。
- 当类似事件再次发生时，系统能够准确、快速地捕捉信号。

### Day 17—21：执行交易与小额实战验证

系统捕捉到信号后，需要能够准确运行既定程序并执行交易。可以采用自动执行，也可以采用半自动方式：涉及资金操作时，由我手动确认并签名。

目标：

- 保证主流场景的既定流程能够准确运行。
- 建立必要的风控与人工确认机制。
- 完成小额实战测试，验证从信号捕捉到交易执行的完整链路。
