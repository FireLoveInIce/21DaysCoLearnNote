### Deploy from a branch

GitHub 直接发布指定分支的根目录或 `/docs` 目录，适合结构简单的静态站点，但不能直接指定 `project/monitor/` 这样的任意嵌套目录。

### GitHub Actions

工作流可以自行检出仓库、选择 `project/monitor/` 作为发布产物，再上传并部署到 Pages。后续也可以在部署前增加构建、测试和校验步骤。

这次切换没有移动源码，只改变了“由谁生成并发布 Pages 内容”。

## 二、谁可以使用，历史存在哪里

当前 GitHub Pages 是公开静态网站，任何知道地址的人都可以访问，不需要账号或钱包授权。每位访问者都通过自己的浏览器直接请求 LI.FI Public API，本项目没有后端服务和数据库。

浏览器 `localStorage` 中保存：

| Key | 内容 |
| --- | --- |
| `lifi-monitor.settings.v1` | 链、Token、金额、报价地址等配置 |
| `lifi-monitor.history.v1` | 最近最多 80 条扫描结果 |
| `lifi-monitor.quote-calls.v1` | 当前浏览器最近两小时的 Quote 次数 |
| `lifi-monitor.token-cache.v1` | LI.FI Token 列表缓存 |
| `lifi-monitor.custom-tokens.v1` | 用户按链添加的自定义中间币 |

因此：

- 历史不会上传到项目服务器；
- 不同设备、浏览器和用户之间不共享；
- 清除站点数据或关闭无痕会话后可能丢失；
- `localStorage` 可被用户修改，不能作为审计或收益证明；
- Quote 请求仍会把链、Token、金额和公开地址发送给 LI.FI，LI.FI 也可能看到请求 IP。

## 三、报价地址的作用

当前页面把“报价地址”同时传入：

```text
fromAddress = 报价地址
toAddress   = 报价地址
```

- `fromAddress` 表示预计由哪个地址提供资产或发起交易；
- `toAddress` 表示执行完成后由哪个地址接收资产。

地址会影响余额模拟、Allowance 检查、Gas 估算、接收者和最终交易 calldata。当前页面开启“快速报价”时跳过余额模拟，因此格式正确的 EVM 地址通常可以用于观察，但为了让 Quote 更接近真实执行环境，应填写实际钱包地址或未来执行合约地址。

报价地址只能填写公开的 `0x...` 地址，绝不能填写私钥或助记词。当前页面只请求 Quote，不签名、不执行，因此填错地址不会立即转走资金；但未来若加入执行功能，随机或错误的 `toAddress` 可能把资产发送给错误接收者。

## 四、计价币、中间币与路径发现

当前扫描模型是：

```text
计价币 → 中间币 → 计价币
```

### 计价币

计价币是本轮扫描的起点、终点和利润结算单位。例如选择 USDC：

- 初始本金以 USDC 输入；
- 最终返回量以 USDC 表示；
- Gas 和未包含费用尽量折算为 USDC；
- 净收益和 ROI 均以 USDC 本位计算。

这里的“计价币”更接近账户本位币，而不完全等同于传统交易所交易对中的 base/quote currency 定义。

### 中间币

中间币是往返过程中的过渡资产，例如：

```text
100 USDC → 0.05165 WETH → 98.519847 USDC
```

其中 USDC 是计价币，WETH 是中间币。更换中间币就是测试另一条往返市场，例如 USDC → cbBTC → USDC。

### 是否需要人工寻找路径

用户当前需要手动选择计价币和中间币，但不需要人工指定 DEX、Aggregator 或逐跳路径。LI.FI 会自动在两个 Token 之间寻找可用路线，页面负责请求正向和反向两个 Quote，并使用保守的 `toAmountMin` 计算结果。

当前版本一次监控一个币对，还不会自动枚举所有中间币。多币种版本需要增加观察列表、并发控制和候选预筛选，否则 Quote 请求量会随链、币种和金额数量快速增长。

## 五、今日功能升级

### 1. 明确显示 Token 合约地址

原选择框只显示 Ticker 和名称，存在同名 Token 被误选的风险。新版下拉项改为：

```text
Ticker · Token 名称 · 完整合约地址
```

选择框下方还会常驻展示计价币和中间币的完整地址。原生 ETH 没有 ERC-20 合约，LI.FI 使用零地址作为其特殊表示。

### 2. 手动添加中间币

用户现在可以展开“手动添加中间币”，填写：

- 当前链的 Token 合约地址；
- Ticker / Symbol；
- Decimals；
- 可选名称。

添加后会自动选为当前中间币，并按链持久化在 `localStorage`。自定义 Token 最多保留 50 个。

Decimals 不能省略，因为页面必须把人类金额转换为链上整数：

```text
1 USDC，Decimals = 6  → 1,000,000
1 WETH，Decimals = 18 → 1,000,000,000,000,000,000
```

地址或 Decimals 填错会造成金额解析错误或 Quote 失败。手动添加只表示允许尝试报价，不代表 LI.FI 一定存在流动性或可用路线。

## 七、风险与挑战

1. **Ticker 不唯一**：必须同时核对链和合约地址，不能只看 Token 名称。
2. **自定义 Token 不等于可信 Token**：恶意 Token、转账税、黑名单和异常 ERC-20 行为仍需额外检测。
3. **两段 Quote 不原子**：第一段和第二段之间的状态可能变化，候选利润不等于可执行利润。
4. **Quote 有时效**：价格、流动性、Gas 和路由会快速变化。
5. **公开 API 有限流**：浏览器本地预算只能保护当前用户，不能代表 LI.FI 的完整服务端额度。
6. **静态页面不能安全保存 API Key**：未来提升额度时应增加受控后端代理。
7. **公开地址存在关联性**：钱包地址本身不是秘密，但会随 Quote 请求发送给 LI.FI。
8. **真实合约执行需要重新验证**：执行合约的调用者、授权、收款和退款地址必须与 Quote 参数保持一致，不能直接假设普通钱包 Quote 可由任意合约原样执行。
