# Day 11 学习计划：五类套利复盘与现实可行性验证

## 今日定位

今天复习跨链套利和稳定币套利，并完成 DEX 内、DEX 间、跨链、三角、稳定币五类方案的统一比较。同时回答一个决定后续开发方向的问题：主流币 DEX 三角套利是否还适合个人参与？

跨链和稳定币场景经常显示出更大的表面价差，但也更容易把库存风险、桥接风险或脱锚风险误认为套利利润；主流币三角路径更容易原子执行，却面临最充分的自动化竞争。因此今天不仅学习原理，还要区分“发现候选信号”“模拟后可以盈利”和“自己真正能够捕获”三个层次。

## 今日目标

- 理解跨链价差和稳定币偏离为什么出现。
- 理解跨链交易缺少全局原子性，以及预存库存的作用。

- 能回答主流币三角套利的候选机会、净利润机会和可捕获机会是否一样多。

- 能设计一段只读观察期，用数据验证某个市场是否值得继续开发，而不是根据展示价差做判断。
- 能比较五类方案的执行条件、基础设施要求和致命风险。
- 为 Day 12–16 确定明确的监控范围和暂不执行范围。

## 当前讨论结论

### 1. 主流币 DEX 三角套利机会多吗？

答案取决于所说的是哪一层机会：

| 层级 | 当前判断 |
| --- | --- |
| 三个池展示价格暂时不一致 | 经常能够观察到 |
| 指定规模逐跳报价后仍有毛利润 | 明显减少 |
| 扣除 Gas、排序费用和预期失败成本后仍为正 | 更少 |
| 在其他搜索者之前完成并真正保留利润 | 对个人非常少 |

主流币交易频繁，更容易被大额 Swap 暂时推离均衡；但 WETH、USDC、USDT 等路径标准化程度高、退出流动性好，也最容易被所有搜索者同时发现和修复。

因此，更准确的结论是：

> 主流币三角套利的候选信号可能不少，但属于个人的可执行净利润机会很少，而且寿命通常很短。

### 2. 是不是因为参与者太多、竞争太大？

是，而且简单套利越容易被共同发现，竞争越容易把利润转移给区块构建和排序环节。公开研究指出，当许多 Searcher 找到相同套利时，套利价值会在竞价中大量让渡给区块提议者；另一项 Ethereum 实证研究虽然针对 CEX–DEX 套利，但同样显示了主流套利市场的集中化：样本中三个 Searcher 获取了约四分之三的交易量和提取价值。

这组证据不能直接给出某条三角路径今天的盈利率，但可以说明：标准化、流动性好的主流套利，已经是高度专业化的竞争市场。

### 3. 普通性能的服务器是不是没机会？

普通服务器并非没有用途。它通常足以完成：

- 维护有限数量白名单池的本地状态。
- 扫描二跳和三跳闭环。
- 计算 V2/V3 指定规模报价。
- 完成历史回放、利润统计和链上调用模拟。

但普通服务器加公共 RPC，不适合直接假设能够稳定抢赢头部池的明显机会。真正的竞争链路是：

```text
状态到达速度
→ 本地状态更新
→ 路径搜索与精确报价
→ 最终交易模拟
→ 签名与提交
→ Builder / Sequencer 接收
→ 获得正确的区块内排序
```

CPU 只是其中一环。很多情况下，决定结果的是数据是否比别人晚到、是否每次都依赖 RPC 往返、模拟是否准确、提交路径是否覆盖目标 Builder，以及愿意支付多少排序费用。

不同网络的环境也不同。针对 2025 年第一季度 L2 活动的研究发现，循环套利相关活动约占 Base 51%、Optimism 55% 的 Gas 使用量，而识别出的相关交互中最终执行 Swap 的比例分别只有约 6.3% 和 12%。这些数字不等于盈利率，但说明低 Gas 网络同样存在大量机器人探测和失败尝试。

### 4. 那么三角套利还值得学习吗？

值得，但当前定位应该调整为：

```text
精确报价和路径搜索的基准场景
→ 只读监控与历史回放
→ 统计真实机会寿命
→ 模拟最终交易
→ 用数据决定是否进入执行阶段
```

不应在没有观测数据前，把“主流币三角套利自动执行”当作第一版系统的盈利假设。

### 5. 当前项目答案

- 保留 DEX 内、DEX 间和三角套利，因为它们适合验证报价、路径和模拟能力。
- 第一阶段只做监控、记录和回放，不与成熟 Searcher 直接竞速。
- 跨链先研究库存和再平衡，不进入非原子实盘。
- 稳定币先做偏离告警、锚点验证和风险过滤。
- 是否开发执行端，由连续观察数据决定，而不是由单次表面价差决定。

## 一、跨链套利为什么出现

同一资产在不同链上的价格可能因为以下原因短暂不一致：

- 各链用户需求和订单流不同。
- 流动性分散，池深和价格曲线不同。
- 桥接需要确认、验证和到账时间。
- 某条链拥堵、暂停充值提现或桥额度不足。
- 原生、封装和第三方桥接资产的信用质量不同。
- 信息和套利资金无法立即跨链同步。

表面上都叫 USDC 或 ETH，不代表它们具有相同合约地址、发行方、赎回路径和风险。

## 二、跨链真正执行需要什么条件

### 1. 两边预存库存

更可靠的执行方式是：

```text
链 A 预先持有计价资产，在低价市场买入目标资产
链 B 预先持有目标资产，在高价市场同时卖出
→ 当场锁定两边成交价
→ 事后通过桥或其他渠道再平衡库存
```

如果必须先在链 A 买入、等待跨链到账、再到链 B 卖出，价差通常会在到账前消失。这更接近承担价格方向风险，而不是即时套利。

### 2. 正确映射资产

每种资产至少记录：

```text
chain_id
contract_address
canonical_asset_id
issuer_or_bridge_provider
mint_and_redemption_path
decimals
withdrawal_status
```

### 3. 两边都具备真实成交深度

需要分别计算指定规模的实际买入成本和卖出所得。任何一边池深不足，都会留下无法平掉的单边库存。

### 4. 有明确的再平衡方案

再平衡不是免费且即时的。需要记录：

- 桥费、Gas 和目标链接收费用。
- 预计到账时间与资金占用成本。
- 桥额度、最小金额和失败退款规则。
- 再平衡期间允许的最大库存偏离。

### 5. 有单边失败处理

两条独立链无法像同链交易一样整体回滚。必须提前回答：

- 一边成交、另一边失败时如何对冲？
- 最多允许持有多少方向性敞口？
- 多久没有恢复库存就停止继续交易？

## 三、跨链最容易死在哪里

| 风险 | 典型问题 | 基本保护 |
| --- | --- | --- |
| 非原子执行 | 一边成交，另一边失败 | 预存库存、并行成交、限制敞口 |
| 桥接延迟 | 到账前价差已经消失 | 桥只用于事后再平衡 |
| 资产映射错误 | 同名资产不能互相赎回 | 按合约与发行路径建模 |
| 桥或跨链消息风险 | 暂停、额度不足、消息失败 | 多渠道监控并设置库存上限 |
| 再平衡成本漏算 | 毛利润被桥费和资金占用吞噬 | 将摊销成本计入每笔交易 |
| 库存失衡 | 一条链资产长期堆积 | 设置目标库存与停止阈值 |
| 链最终性差异 | 一边交易确认后另一边被重组 | 按链分别定义确认和风控规则 |

## 四、稳定币套利为什么出现

稳定币可能因为以下原因偏离目标价格：

- 某个池短期买卖失衡。
- CEX 充值或提现暂停。
- 铸造、赎回存在门槛、时间或地区限制。
- 市场担忧储备、发行方、托管方或桥接资产。
- 借贷清算和杠杆平仓集中发生。
- 不同链上的稳定币库存无法及时再平衡。

稳定币价格偏离并不自动等于无风险套利。市场愿意用 `0.97 USDC` 卖出某稳定币，可能是暂时流动性问题，也可能是在为真实信用风险定价。

## 五、稳定币套利与方向性押注的边界

### 更接近可锁定套利

```text
DEX 以 0.990 USDC 买入稳定币
CEX、赎回通道或另一深度市场同时以 0.998 USDC 卖出
两边已经具备库存或可以原子完成
全部费用后利润仍为正
```

### 更接近方向性押注

```text
以 0.970 USDC 买入
没有可以同时锁定的卖出或赎回通道
只能等待价格未来恢复到 1 美元
```

后一种策略承担发行方信用、储备、监管、赎回和继续脱锚风险，不能因为资产名称中有“稳定币”就当作套利。

## 六、稳定币真正执行需要什么条件

- 发行方铸造、赎回或可靠的二级市场出口正常。
- 自己确实拥有使用充值、提现或赎回通道的权限。
- 两边有足够的可成交深度，并能同时锁定价格。
- 稳定币的美元锚点来自多个独立来源，而不是固定写死为 1。
- 完整计算交易费、Gas、提现费、桥费、资金占用和再平衡成本。
- 为每种稳定币和桥接版本分别设置最大单笔金额与总敞口。

建议维护动态锚点：

```text
asset_usd_price = weighted_median(
    deep_dex_price,
    cex_orderbook_price,
    independent_oracle,
    verified_redemption_value
)
```

任一来源异常时，应降低权重或暂停该资产，而不是继续强制按 1 美元计算。

## 七、稳定币最容易死在哪里

- 把结构性脱锚当成短期流动性失衡。
- 只看到买入折价，没有确认卖出或赎回出口。
- CEX 盘口存在价格，但充值、提现已经暂停。
- 混淆原生稳定币和第三方桥接版本。
- 使用过期预言机或单一低流动性池作为美元锚点。
- 低估挤兑时的滑点、赎回排队和链上拥堵。
- 为追求小额价差承担过大的发行方或桥接资产敞口。

## 八、五类方案统一判断矩阵

| 场景 | 机会来源 | 是否容易原子执行 | 关键基础设施 | 主要致命风险 | 当前建议 |
| --- | --- | --- | --- | --- | --- |
| DEX 内 | 同一 DEX 多池、费率或路径价格不同步 | 同链通常可以 | 池状态、精确报价、执行模拟 | 滑点、状态变化、非标准池 | 优先监控与模拟 |
| DEX 间 | 不同 DEX 的流动性与订单流分散 | 同链通常可以 | 多 DEX 适配、资产标准化 | 只看 Spot Price、抢跑 | 优先监控与模拟 |
| 三角套利 | 三个交易对的隐含汇率不一致 | 同链通常可以 | 路径搜索、逐跳报价、提交路径 | 多跳费用、机会过期、排序竞争 | 优先监控与回放，不预设能稳定执行 |
| 稳定币套利 | 流动性、赎回或信用差异造成偏离 | 取决于退出通道 | 动态锚点、赎回与 CEX 状态 | 真实脱锚、出口暂停 | 先做告警和风险过滤 |
| 跨链套利 | 各链库存、需求和到账时间不同 | 通常不可以 | 多链库存、桥监控、对冲 | 单边成交、桥延迟、库存失衡 | 先做只读观察 |

## 九、统一可执行性检查

### Gate 1：机会为什么存在

必须能解释价格差来自订单冲击、流动性分散、路径汇率、库存失衡还是信用风险。无法解释的高收益优先视为风险信号。

### Gate 2：资产是否真的相同或可交付

检查链、合约、发行方、桥接来源、精度和赎回路径。

### Gate 3：数据是否及时且一致

记录区块、时间、数据年龄、订单簿序号和数据源状态。

### Gate 4：指定规模能否完整成交

使用真实 `amountOut`、订单簿 VWAP 和完整路径，不使用展示价格代替执行价格。

### Gate 5：成本后是否盈利

```text
net_profit =
    final_proceeds
    - initial_cost
    - trading_fees
    - gas
    - slippage
    - priority_or_private_submission_cost
    - bridge_or_rebalance_cost
    - funding_cost
    - expected_failure_cost
    - risk_buffer
```

### Gate 6：失败后会留下什么

- 同链原子路径通常只损失 Gas。
- 跨链或 DEX/CEX 路径可能留下库存和方向性敞口。
- 等待稳定币恢复锚定可能承担全部脱锚损失。

### Gate 7：最终路径是否模拟和复查

新区块、预言机、池状态、桥状态或充值提现状态变化后，必须重新判断。

## 十、后续系统优先级

### P0：第一版必须支持

- 单链 Token、Pool 和同区块池状态标准化。
- V2/V3 指定规模报价。
- DEX 内、DEX 间和最多三跳的闭环路径扫描。
- 手续费、Gas、滑点和安全缓冲后的净利润计算。
- 信号记录、历史回放和只读告警。
- 候选机会、净利润机会、模拟成功机会的分层计数。
- 数据延迟、机会寿命和下一区块存活情况统计。

### P1：完成 P0 后增加

- Quoter 校验和最终 calldata 模拟。
- 动态稳定币锚点与风险白名单。
- 数据年龄、模拟状态和失败原因记录。
- 对高置信度信号进行人工确认。
- 对照真实链上成交，记录机会由谁捕获以及自己的信号晚了多久。

### P2：暂时只观察

- 跨链价差、桥状态和多链库存模型。
- CEX 订单簿与充值提现状态。
- V4 动态费率或会修改 Swap 结果的 Hook。
- 主流币三角套利的私有提交、Builder 覆盖与竞价策略。

### 当前明确不做

- 清算策略。
- 主动抢跑、夹子攻击等攻击性 MEV 策略。
- 未完成持续模拟和风控前的自动真金执行。

抢跑、交易排序和 MEV 仍作为风险因素进入模型，但不作为独立盈利方向。

- 能解释为什么主流币三角套利“信号可能多，但个人可捕获机会少”。
- 能说明服务器 CPU、RPC 延迟、状态同步和交易排序分别影响哪一段链路。
- 能用候选数、净利润数、模拟成功数和机会寿命评价市场，而不是只展示最高收益案例。
- 能为五类方案分别指出关键执行条件和致命风险。
- 能明确第一版系统为什么优先同链监控，而不是同时覆盖所有方向。
- 能列出 Day 12 数据采集模块的最小输入字段。

## 十五、阶段复盘

1. 五类方案中，哪些可以在同一笔链上交易里完整回滚？
2. 哪些方案最依赖库存，库存成本应该如何分摊？
3. 哪些高收益信号更可能是资产风险而不是套利机会？
4. 当前个人能力和基础设施最适合从哪类场景开始？答案：从有限池集合的同链只读监控、精确报价和历史回放开始。
5. 普通服务器最大的限制一定是计算性能吗？答案：不一定，更常见的瓶颈是 RPC 数据到达、状态同步、模拟往返和提交排序。
6. 下一阶段的监控系统如何证明一条信号不是过期或表面盈利？答案：记录一致快照，完成指定规模逐跳报价，扣除全部成本，执行最终路径模拟，并统计机会寿命。

## 十六、7–14 天观察指标

```text
candidate_count                 # 展示价格或理论汇率出现偏差
gross_positive_count            # 指定规模逐跳后毛利润为正
net_positive_count              # 扣除全部成本后净利润为正
simulation_success_count        # 最终 calldata 模拟成功
survived_next_block_count       # 到下一块仍然存在
captured_by_other_searcher_count
opportunity_lifetime_ms
data_age_ms
quote_latency_ms
simulation_latency_ms
expected_profit_after_failures
```

观察结束后再回答：

- 净利润机会是否具有足够样本量？
- 自己首次发现时，机会是否已经被别人捕获？
- 延迟主要来自节点、程序计算还是模拟？
- 失败成本计入后，长期期望收益是否仍为正？
- 是否拥有任何不同于公开搜索者的路径、数据或执行优势？

如果这些问题没有得到正面证据，就继续把三角套利定位为监控和工程验证场景，而不是进入真实资金执行。
