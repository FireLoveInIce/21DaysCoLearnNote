# Day 06：DEX 内套利

## 今日目标

- 理解同一 DEX 内价差产生的原因。
- 区分“存在价差”和“能够盈利”。
- 掌握包含手续费、Gas、滑点和安全边际的利润判断方法。
- 知道套利执行需要的数据、条件和主要风险。

## 一、什么是 DEX 内套利

同一个 DEX 中，不同资金池、费率池或交易路径可能对同一资产给出不同价格。

例如：

```text
Pool A：1 ETH = 3000 USDC
Pool B：1 ETH = 3030 USDC

套利路径：USDC → Pool A 买 ETH → Pool B 卖 ETH → USDC
```

价差通常来自：

- 大额交易使某个池的价格暂时偏移。
- 不同池的流动性深度、费率和状态不同。
- V3 集中流动性、V4 Hook 或动态费率造成报价差异。
- 套利交易尚未将各池价格重新拉近。

常见路径包括同交易对双池、不同费率池，以及 `USDC → WETH → USDT → USDC` 这类多跳循环。

## 二、利润如何判断

看到价格差不代表可以盈利。交易会改变池中价格，必须使用实际输入金额逐跳报价。

对于 V2 恒定乘积池：

```text
amountInAfterFee = amountIn × (1 - fee)
amountOut = reserveOut × amountInAfterFee
            ──────────────────────────────
            reserveIn + amountInAfterFee
```

V3/V4 涉及 Tick、流动性区间和 Hook，应固定 `blockTag`，使用 Quoter 或完整交易模拟获得实际输出。

统一计价资产后：

```text
毛利润 = 最终输出 - 初始投入

净利润 = 毛利润
         - Gas 成本
         - 闪电贷费用
         - Builder/优先费
         - 其他执行成本

可执行利润 = 净利润 - 滑点与状态变化安全边际
```

只有 `可执行利润 > 最低目标利润` 时，才应把它视为候选机会。

交易规模也不能无限增大：规模越大，价格影响越大，最终会吞噬价差。实际要寻找的是“净利润最高的输入规模”，可以先扫描多组输入金额，再在最优区间细化搜索。

## 三、执行条件与主要风险

执行条件：

- 所有报价和池状态来自同一个区块。
- 路径有效、流动性充足，且滑点和 Gas 可控。
- 能在一笔交易中原子完成；任何一步失败时整笔回滚。
- 提交前已模拟完整交易，而不只是单独调用 Quoter。

最容易失败的地方：

- 使用旧状态，交易上链前机会已经消失。
- 被抢跑或交易排序改变。
- 遗漏手续费、Gas、优先费等成本。
- Token decimals、取整或报价方向错误。
- 交易规模过大，价格影响吞噬利润。
- V4 Hook 改变费用、资产流或执行结果。
- 模拟成功，但真实执行时状态变化导致回滚。

## 四、复盘问题与答案

### 1. 哪个成本影响最大？

没有固定答案。小额交易通常受 Gas 影响最大，大额交易通常受价格影响和滑点影响最大；竞争激烈时，抢跑、排序和状态变化风险可能最关键。因此必须针对每条路径和输入规模单独计算。

### 2. 判断机会至少需要哪些数据？

- 池地址或 PoolKey、Token 顺序和 decimals。
- 同一 `blockTag` 下的池状态、手续费和实际报价。
- 套利方向、输入金额与每一跳输出。
- Gas 使用量、Gas 价格及其统一计价后的成本。
- 最低目标利润与安全边际。
- V4 场景还需要 Hook 地址、权限、状态和真实 `hookData`。

### 3. 这个场景适合自动化吗？

适合，而且多数机会持续时间很短，通常必须自动化：

```text
监听池状态 → 快速筛选路径和规模 → 精确报价
           → 模拟完整交易 → 检查净利润 → 原子提交
```

未知 Hook、无法模拟、状态不一致或安全边际不足的路径，不应进入自动执行器。
